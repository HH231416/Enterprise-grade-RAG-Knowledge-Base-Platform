# Hybrid 检索受控回归集报告

## 目的

该报告用于证明混合检索融合逻辑在“企业规则编号、系统名称、角色术语”等精确词场景的行为正确性。它是一个可重复运行的受控排名回归集，不替代真实业务语料上的离线/线上评估。

## 运行方法

```powershell
python scripts\interview_metrics_benchmark.py
```

## 数据口径

- 数据集：`controlled-enterprise-rule-regression-v1`
- Query 数：12 条
- 内容：HR、财务、IT、安全四类企业规则；前 3 条为制度编号与精确术语难例，第 5、6 条为词面缺失的同义改写难例。
- Dense 基线：冻结的候选排序分数，用于稳定复现“语义近似但精确编号不占优”的典型失败模式。
- Sparse 召回：项目实际 `BM25Index`，采用中文二元切词、倒排索引和 BM25 评分。
- 融合：项目实际 `HybridRetriever(alpha=0.7)`，使用 Min-Max 归一化与加权融合。

## 结果

| 方案 | Hit@1 | MRR | 正确 Top1 数 |
|---|---:|---:|---:|
| 冻结 Dense 基线 | 58.3% | 0.792 | 7/12 |
| Dense + BM25 Hybrid | 83.3% | 0.917 | 10/12 |

三条制度编号/精确术语难例中，Dense 基线均将正确 Chunk 排在第 2；Hybrid 通过 BM25 的精确词匹配和融合排序将其提升到第 1。两条词面缺失的同义改写 Query 仍排在第 2，说明 BM25 无法弥补 Embedding 对同义表达的排序偏差；其余七条 Query 保持正确 Top1，没有发生融合回退。

## 简历与面试口径

可以说：

> 在 12 条企业规则专有词与同义改写受控回归集上，Hybrid 将 Hit@1 从 58.3% 提升到 83.3%，MRR 从 0.792 提升到 0.917；其中两条词面缺失 Query 仍未命中 Top1，我把它们保留为回归样本，后续用更强 Embedding、LLM Rewrite 或 Rerank 继续优化。

不能说：

> 线上真实业务检索准确率提升 33.3%。

因为当前数据集的作用是验证融合逻辑和典型失败模式，不代表真实线上流量分布。
